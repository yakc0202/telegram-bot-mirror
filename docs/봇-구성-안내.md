# 텔레그램 주식정보 봇 구성 안내

이 문서는 공개 미러(`telegram-bot-mirror`)에도 올라간다. 토큰·키·채팅방 ID 같은 보안 값은 쓰지 않는다(`mirror-push.sh`가 검사).
처음 보는 사람이 이 문서 하나로 전체를 알 수 있게 쓴다.
문장 하나에 사실 하나를 쓴다. 같은 것은 늘 같은 이름으로 부른다.

기준일: 2026-10-13

---

## 1. 한 줄 요약

봇은 텔레그램 주식·투자 채널 19곳을 감시하다가, 같은 내용은 하나만 남기고 요약을 붙여 내 채널로 보낸다.
하루 두 번(08시·18시) 금리·에너지 중심의 시장 정리를 보낸다.

```
[텔레그램 채널 19곳]
        │  새 메시지
        ▼
[유저봇(내 텔레그램 계정)] ── 실시간 수신
        │
        ▼
[중복 판단] 해시 → 키워드·숫자 유사도 → 애매하면 AI(Gemini)
        │
        ├─ 중복 → 버림
        └─ 새 정보 → AI 요약 → [알림 봇] → [요약 채널]
                                              ▲
[08시·18시] 모은 메시지 + 시세·금리 데이터 → AI 정리 ──┘ (텍스트 + HTML 파일)
```

### 3-3. 비밀값은 어디에 있나

```
텔레그램 API ID/Hash, 봇 토큰, Gemini 키, 채널 ID ──► ~/.config/telegram-bot/.env
유저봇 로그인 상태 ──► 운영 폴더 stock_dedup_session.session (= 계정 접근 권한)
GitHub 접근 ──► 러너 등록 토큰 (러너 폴더)
```

- `.env`와 세션 파일은 git에 없다. 배포 rsync도 건드리지 않는다.
- 세션 파일을 가진 사람은 내 텔레그램 계정을 쓸 수 있다. 복사·공유하지 않는다.
- `stderr.log`에는 네트워크 재시도 경고에 봇 토큰이 평문으로 찍힐 수 있다.

## 4. 코드 구성 (저장소 파일)

### 4-1. 폴더 지도

```
telegram-bot/
├─ main.py            ← 봇 전부
├─ requirements.txt   ← telethon, anthropic, python-dotenv, requests, yfinance
├─ .github/workflows/deploy.yml ← 배포 (push → rsync → venv → 문법 검사 → 재시작)
├─ docs/봇-구성-안내.md ← 이 문서
├─ mirror-push.sh     ← 공개 미러 동기화(보안 값 가림·검사)
├─ README.md          ← 개요
├─ AGENTS.md          ← 에이전트 작업 규칙
├─ SYNC.md            ← 지금 상태 요약
├─ REQUESTS.md        ← 요청 기록
│
│  (git 밖, 운영 폴더에만 있음 — 배포 rsync 제외)
├─ run_bot.sh, CLAUDE.md, list_chats.py
├─ .venv/
├─ dedup_history.db*, digest_sent_state.json
└─ *.session
```

### 4-2. 봇 안에서 도는 일

| 이름 | 언제 | 하는 일 |
|---|---|---|
| `handler()` | 새 메시지마다 | 앨범은 2초 모아서 `process_event()`로 넘김 |
| `process_event()` | 메시지 1건 | 잡담 필터 → 중복 판단 → 요약 → 전송 → 기록 |
| `is_duplicate()` | 메시지 1건 | 해시 → 링크 → 예외 필터 → 유사도 → 애매하면 AI |
| `_digest_loop` ×2 | 30초마다 | 08시·18시 회차가 밀렸는지 실제 시계로 확인하고 정리 실행 |
| `_run_digest()` | 회차마다 | 메시지 모으기 + 시세·금리 조회 → AI 정리 → 텍스트·HTML 전송 |
| 재전송 루프 | 30초마다 | 전송 실패한 미디어 다시 보내기 |
| `_catch_up_missed_messages` | 시작할 때 | 꺼져 있던 동안의 메시지를 채널별 처리 위치부터 다시 처리 |
| 예방 재연결 | `RECONNECT_INTERVAL_HOURS`마다 | 텔레그램 연결을 새로 맺기 |

### 4-3. 메시지 1건의 처리 순서

```
새 메시지 도착
  │
  ├─① 스티커·투표? ──────────── 무시
  ├─② 잡담 필터(AI): 주식과 무관? ── 버림
  ├─③ 완전히 같은 글(해시)? ───── 버림
  ├─④ 같은 링크 + 문구 비슷? ──── 버림
  ├─⑤ 국가·종목코드·날짜·만기·품목 등이 다름? ── 새 정보로 확정
  ├─⑥ 키워드·숫자 유사도
  │     ├─ 0.6 이상 ── 버림
  │     ├─ 0.25~0.6 ── AI에게 "같은 정보냐" 확인
  │     └─ 0.25 미만 ── 새 정보
  ├─⑦ AI 요약 붙여서 요약 채널로 전송 (4096자 넘으면 (1/N)로 분할)
  └─⑧ 데이터베이스에 기록, 채널 처리 위치 갱신
```

### 4-4. 정리 회차 처리

```
30초마다:
  지금 회차(오늘 18:00 또는 어제 18:00 …)를 처리했나? ── 예 → 대기
        │ 아니오
        ├─ 다음 회차 시각이 이미 지남? ── 예 → 보내지 않고 처리된 것으로 기록
        ├─ 3번 실패함? ── 예 → 포기하고 기록 (경고 채널)
        └─ 정리 실행 → 텍스트 전송 직후 정리 기록에 회차 저장 → HTML 전송
```

## 5. 바꾸고 올리는 법 (배포)

| 바꾼 것 | 하는 일 | 봇 재시작 |
|---|---|---|
| `main.py`, `requirements.txt`, `deploy.yml` | 문법 검사 → 커밋 → `git push origin main` | 예 (자동) |
| `*.md` 문서만 | 커밋 → push | 아니오 (`paths-ignore`) |
| 무엇이든 바꾼 뒤 | `./mirror-push.sh` → `--push` (공개 미러) | 아니오 |
| `.env` | 직접 수정 → 서비스 재시작 | 수동 |
| `run_bot.sh`, plist | 직접 수정 (plist는 관리자 암호 필요) | 수동 |

```
git push origin main
  └─► 러너: 체크아웃 → rsync(--delete, .git·.env·세션·DB·*.sh·*.json·CLAUDE.md 제외)
        → venv에 패키지 설치 → py_compile → launchctl bootout/bootstrap/kickstart
```

- 서비스 재시작 명령 3개만 러너 계정에 암호 없이 허용돼 있다(sudoers).
- 운영 폴더는 `~/Documents` 아래로 옮기지 않는다. macOS가 그 폴더를 보호해서 서비스가 실행되지 않는다.

## 6. 클라우드로 옮길 수 있나 (검토)

### 6-1. 결론

옮길 수 있다. 추천은 **AWS Lightsail 서울, Linux 1GB, 월 $7**이다.
옮기는 가장 큰 이유는 운영 맥이 잠들면 봇이 멈추는 문제가 없어지는 것이다.
옮기지 않고 잠자기만 막는 방법(월 0원)도 있다. 6-4에 비교했다.

### 6-2. 왜 서버(항상 켜진 컴퓨터)여야 하나

- 유저봇은 텔레그램과 연결을 계속 열어 둬야 메시지를 실시간으로 받는다.
- Lambda는 한 번에 최대 15분만 돈다. 그래서 Lambda로는 못 한다. 서랍(bookmark-shelf)과 다른 점이다.
- 컨테이너 서비스(Fargate)도 되지만, 이 크기에서는 Lightsail보다 비싸고 설정할 것이 많다.

### 6-3. 선택지와 월 비용

| 선택지 | 월 비용 | 메모리 | 판단 |
|---|---|---|---|
| Lightsail 서울 1GB (IPv4) | **$7** | 1GB | 추천. 디스크 40GB·전송 2TB 포함, 고정 요금 |
| Lightsail 서울 512MB (IPv4) | $5 | 0.5GB | 봇 136MB + 패키지 설치·시세 조회 순간 사용량이 빠듯함 |
| Lightsail IPv6 전용 | $3.5~5 | — | 안 됨. github.com이 IPv6를 지원하지 않아 배포가 막힘 |
| EC2 t4g.micro 서울 | 약 $12 (근사치) | 1GB | 인스턴스 약 $7.6 + 공인 IPv4 $3.65 + 디스크 8GB 약 $0.7. Lightsail보다 비쌈 |
| 운영 맥 유지 + 잠자기 방지 | 0 | — | 6-4 참고 |

- 변하지 않는 비용: Gemini(무료 한도), 텔레그램, Yahoo, FRED는 지금처럼 0원이다.
- 전송량: 메시지·사진 전달 수준이라 포함량(2TB) 안이다.
- 1달러 1,400원으로 치면 Lightsail 1GB는 월 약 1만 원이다.
- 가격은 AWS Lightsail 요금 페이지(2026-10-13 확인) 기준이다. EC2 금액은 시간당 요금으로 계산한 근사치다.

### 6-4. 클라우드 vs 맥 유지

| | Lightsail 1GB | 운영 맥 + 잠자기 방지 |
|---|---|---|
| 월 비용 | $7 | 0 |
| 덮개를 닫아도 계속 돎 | 예 | 전원 연결 + 잠자기 끄기(`sudo pmset -a disablesleep 1`) 설정 시 예 |
| 맥을 들고 나가도 돎 | 예 | 아니오 |
| 정전·OS 업데이트 재부팅 | AWS가 관리 | 직접 확인 |
| 맥 배터리·발열 부담 | 없음 | 상시 전원·발열 |
| 옮기는 작업 | 반나절 (6-6) | 명령 한 줄 |

- 운영 맥의 지금 설정: 전원 연결 시 `sleep 0`, 배터리일 때 `sleep 1`(1분), `disablesleep`은 꺼져 있다.
- 그래서 전원을 빼거나 덮개를 닫으면 잠든다. 2026-10-12 13:54에도 배터리 상태에서 잠들었다(`pmset -g log`).

### 6-5. 옮길 때 위험

- **텔레그램 로그인**: 세션 파일을 복사해 쓰면 두 곳에서 같은 세션이 돌 수 있다. 운영 맥의 봇을 먼저 끄고, 서버에서 전화번호 인증으로 새로 로그인하는 편이 안전하다.
- **데이터센터 IP**: 텔레그램은 데이터센터 IP의 유저봇에 더 민감할 수 있다. 처음 며칠은 계정 제한 알림을 지켜본다.
- **Yahoo 시세 차단**: `yfinance`는 클라우드 IP에서 "Too Many Requests"로 막히는 사례가 보고돼 있다. 막히면 정리에서 시세가 빠진다(금리는 FRED라 영향 없음). 하루 2번 조회라 위험은 낮다.
- **세션 파일 보관**: 서버 디스크에 계정 접근 권한이 놓인다. 파일 권한 600, SSH 키 로그인만 허용, 방화벽은 SSH만 연다.
- **배포 방식 변경**: 러너가 macOS ARM64에서 Linux x86_64로 바뀐다. `deploy.yml`의 `runs-on` 라벨과 재시작 명령(launchctl → systemd)을 바꿔야 한다.
- **Python 버전**: 지금 3.9 → Ubuntu 24.04는 3.12. 옮기기 전에 3.12에서 한 번 돌려 본다.

### 6-6. 옮기는 순서 (하게 되면)

```
① Lightsail 서울 1GB(Ubuntu) 만들기, 고정 IP 붙이기, 방화벽 SSH만
② python3-venv 설치, 저장소 clone, ~/.config/telegram-bot/.env 복사(scp)
③ dedup_history.db, digest_sent_state.json 복사 (처리 위치·정리 기록 유지)
④ 운영 맥 서비스 끄기 (launchctl bootout)
⑤ 서버에서 python3 main.py 한 번 실행 → 전화번호·인증 코드로 로그인 → 세션 생성
⑥ systemd 서비스 등록 (Restart=always), run_bot.sh 알림 로직 그대로 사용
⑦ 서버에 러너 설치, deploy.yml 라벨·재시작 명령 변경, sudoers에 systemctl restart만 허용
⑧ 하루 지켜보기: 실시간 전달, 08시·18시 정리, 로그 채널 경고
⑨ 운영 맥의 러너·서비스 제거
```

## 7. AI를 Gemini 대신 Claude Code·Codex로 바꿀 수 있나 (검토)

### 7-1. 결론

메시지마다 부르는 AI는 Gemini로 두고, **08시·18시 정리만 Claude Code·Codex로 바꿨다**(Claude → Codex → Gemini 순).
전부 바꾸면 호출 수가 구독 한도를 넘고, 호출마다 프로그램을 새로 띄워 느려진다.

### 7-2. 봇이 AI를 부르는 곳과 횟수 (로그 기준)

| 용도 | 함수 | 평일 하루 횟수 | 특징 |
|---|---|---|---|
| 잡담 필터 | `classify_is_stock_related` | 들어온 메시지마다 (수백~1,000) | 짧은 답(분류) |
| 중복 확인 | `ask_llm_same_info` | 약 750~800 | 짧은 답(SAME/DIFFERENT), 처리 잠금을 쥔 채 실행 |
| 요약 | `summarize_*` | 약 550~650 (보낸 메시지 수) | 몇 줄 |
| 사진 판정 | `classify_image_is_stock_related` | 약 60~80 | 이미지 입력 |
| 일간 정리 | `generate_daily_digest` | 2 | 긴 입력(모은 메시지 전부)·긴 출력, 품질이 가장 중요 |

합계: 평일 하루 약 2,000회 이상. 주말은 절반 이하.
측정: `stderr.log` 2026-10-09·10-10·10-12의 "요약 채널에 전송 완료", "LLM 판단", "이미지/미디어" 줄 수.

### 7-3. 전부 바꾸면 생기는 문제

- **속도**: 이 맥에서 `claude -p`는 짧은 질문 하나에 약 4.7초, `codex exec`는 약 5.9초 걸렸다(2026-10-13 측정). 하루 2,000회면 순수 대기만 약 3시간이다.
- **밀림**: 중복 확인은 처리 잠금을 쥔 채 돈다. 한 번에 5초씩이면 장 시작 전후처럼 메시지가 몰릴 때 대기열이 길어진다.
- **한도**: Claude·ChatGPT 구독의 사용 한도는 개발용 대화 기준이다. 하루 2,000회는 넘을 가능성이 크고, 넘으면 내 Claude Code·Codex 작업과 서랍 worker도 같이 막힌다.
- **비용 이점이 없음**: Gemini는 지금 무료 한도 안이라 0원이다.

### 7-4. 정리만 바꾸면 얻는 것

- 정리는 하루 2번이라 한도·속도 문제가 없다(한 번에 수십 초~몇 분이어도 됨).
- 금리·에너지 연결 해석, 가설 반증처럼 추론이 필요한 부분이라 큰 모델의 이점이 가장 크다. 지금 모델은 가벼운 `gemini-3.1-flash-lite`다.
- 순서: Claude → Codex → Gemini(`DIGEST_CLI_PROVIDERS=claude,codex`). 앞의 것이 실패하면 다음으로 넘어간다.
- 같은 입력 비교(10/13 08시 회차): Gemini 6초·얕음, Claude 81초·가장 구체적, Codex 79초·신중하지만 짧고 링크를 붙임.

### 7-5. 구현 (`main.py`)

```
generate_daily_digest ─► call_digest_llm
                           ├─ _call_cli("claude"): claude -p --tools "" (빈 임시 폴더, 표준입력)
                           ├─ _call_cli("codex"):  codex exec -s read-only --ephemeral -o 파일 -
                           └─ 둘 다 실패 → call_llm (Gemini)
시작할 때 check_digest_cli_auth: claude auth status / codex login status 결과를 로그로 남김
```

- 환경변수: `DIGEST_CLI_PROVIDERS`(기본 `claude,codex`, 비우면 CLI 안 씀), `DIGEST_CLI_TIMEOUT`(420초), `DIGEST_CLAUDE_MODEL`, `DIGEST_CODEX_MODEL`.
- CLI 위치는 `shutil.which` → `/opt/homebrew/bin` 순으로 찾는다(서비스 PATH에 없음).
- 답에 붙은 마크다운 링크 `[제목](주소)`는 제목만 남긴다.
- Claude가 서비스 환경에서 키체인 로그인을 못 읽으면 시작 로그에 경고가 뜬다. 그때는 `claude setup-token`으로 만든 토큰을 `.env`의 `CLAUDE_CODE_OAUTH_TOKEN`에 넣는다.

- 클라우드(6장)로 옮기면 서버에도 두 프로그램 설치와 로그인이 따로 필요하다.
- 구독 계정을 자동화에 쓰는 것은 각 회사 약관·한도 정책을 따른다. 정책은 바뀔 수 있다.

## 8. 낱말 풀이

| 낱말 | 뜻 |
|---|---|
| 유저봇 | 봇 계정이 아니라 내 계정으로 로그인해 자동으로 읽는 프로그램 |
| 세션 파일 | 텔레그램 로그인 상태를 저장한 파일. 있으면 다시 인증하지 않는다 |
| MTProto | 텔레그램 앱이 쓰는 통신 방식. 유저봇은 이것으로 메시지를 받는다 |
| Bot API | 봇 계정이 메시지를 보내는 통로 |
| LaunchDaemon | 로그인과 상관없이 맥이 켜져 있으면 도는 서비스 |
| self-hosted runner | GitHub Actions 작업을 내 컴퓨터에서 실행하는 프로그램 |
| rsync | 폴더를 다른 폴더와 똑같이 맞춰 복사하는 도구. `--delete`는 없는 파일을 지운다 |
| 회차 | 08시·18시 정리 한 번. "10/13 18:00 회차"처럼 부른다 |
| BEI | 기대 인플레이션(명목금리 − 실질금리) |
| Lightsail | AWS의 고정 요금 가상 서버 |
| `claude -p` / `codex exec` | Claude Code·Codex를 대화창 없이 한 번 실행해 답만 받는 방식 |
| systemd | 리눅스에서 서비스를 켜 두고 죽으면 재시작하는 장치(launchd와 같은 역할) |
